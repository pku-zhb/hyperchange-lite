# Preview 7: a single focused preview and stable notification groups

The owner rejected Preview 6's remaining text density and independent scene
selection. All feedback received before delivery belongs to this same iteration,
including notification group disorder.

## UI contract

Every feature page uses the same vertical structure on every width: one pinned
rendered sample above one scrollable controls list. No preview caption, status
paragraph, preview selector, separate preview page or always-visible playback /
background controls compete with the settings. The current project, first
visible setting and explicit edits choose a representative sample automatically.
An explicit edit keeps priority until the user actually scrolls again.

Persistent descriptions and help paragraphs are removed. HMC-sensitive controls
carry only the short title marker “注意兼容”. Essential numeric validation,
errors and destructive-action confirmation remain in dialogs. Accessibility can
expose native/schematic status without reserving visible preview space. Existing
preference keys, values, defaults, exact entry and common slider ranges remain.

## Preview behavior

The renderer hides its caption with zero layout allocation in render-only mode.
Focus includes the exact setting key, so entry and exit inputs play their own
motion, and volume width, pop and nudge use distinct demonstrations. Slider
updates are coalesced before playback reads the saved configuration. Disabled
features retain their current ordinary appearance.

Control Center geometry selects one representative matching the edited tile,
slider, media, device or secondary-panel radius. Volume timer geometry selects
the timer alone. Ordinary volume rendering uses the same ringer visibility policy
as the system adapter, and material-only edits do not start unrelated motion.
Native preview remains an App sample, not evidence of SystemUI activation or
pixel-identical OEM scene recipes. No new rendering engine or system owner is added.

## Notification group repair

Confirmed source defects included stale sessions validated only by count, compact
measurement surviving expansion/member changes, native child application after the
summary callback, and unhandled extra children beyond the three-card presentation.
The linear scale formula also reduced the third card to zero at the legal 0.5
ratio. These are source findings, not a claim of an observed phone trace.

Sessions now validate the complete ordered member identity, parent and native GONE
participation. Replacements, mutations, expansion and scope/config changes retire
owned geometry and measurement together. Ordinary unchanged state updates retain
valid measurement. Restore respects newer OEM values and native child ordering.
All selected child states must exist before any mutation. Extra eligible members
are hidden reversibly, including their animation alpha/hidden state where the
verified type-compatible fields exist; visible cards receive their current owned
alpha and visibility after the native container pass. Native GONE rows stay excluded.
Per-layer scaling is multiplicative, so even the extreme legal ratio stays positive.

Host regressions cover equal-count replacement, reorder, moving owners, extra
member replacement, native filtering, independent measurement ownership and exact
preview routing. Native rendering, animation integration and touch behavior still
require user acceptance; no phone GUI, screenshot or scope restart was used.

## Focused acceptance

1. In Material, Notifications and Volume, scroll and edit controls: only one
   rendered preview stays above the list, switches automatically and has no
   persistent explanatory text. HMC-sensitive titles show only the short marker.
2. Change enter/exit or volume motion inputs and confirm the relevant preview
   uses them without a second selection.
3. For a real notification group, expand/collapse, add/remove a member and disable
   group stacking. Cards must not overlap stale members or retain old transforms.
